# QuotaPal 开发与验收 Checklist

记录日期：2026-10-09。状态：开发进行中。进度与验证证据见 [开发进度](PROGRESS.md)。

首版范围为 Android 平台的 Codex 单账号额度监控与桌面小组件，发布路线为先自用验证，再公开发布。完整产品范围、技术方案、阶段交付物与工期见 [开发计划](DEVELOPMENT_PLAN.md)，阶段跟踪见 [GitHub milestones](https://github.com/tsonglew/QuotaPal/milestones)。

本清单共 51 项。检查项只有在实际执行并留下可验证结果后才能勾选；创建文档或 GitHub milestone 不代表完成开发或接入验证。

## A. 开工前接入验证（M0）

首先解决手机能否独立、持续获取真实 Codex 额度的不确定性。M0 的结论决定后续开发是否按原范围推进。

- [x] **A01** 确认目标是 Codex 订阅额度，明确首批支持的账号类型。
- [ ] **A02** 核实独立 Android 客户端可采用的认证流程及适用范围。
- [ ] **A03** 分别验证“能够登录”和“能够读取额度”，记录实际需要的权限。
- [x] **A04** 明确应用只做监控；如凭据权限更广，准确说明，不能称其为“只读凭据”。
- [ ] **A05** 验证首次连接、取消授权、授权超时、重新连接、撤销授权。
- [ ] **A06** 验证 token 到期后的续期，以及并发续期时的正确性。
- [ ] **A07** 核实账号、工作区和额度之间的对应关系。
- [ ] **A08** 保存脱敏样本，覆盖单窗口、多窗口、缺失字段、额度耗尽。
- [ ] **A09** 决定接入方案是否适合自用，以及公开发布还缺哪些条件。

## B. 产品和数据规格（M1）

冻结页面、小组件和数据语义，确保 App 与小组件采用相同的额度解释与状态规则。

- [x] **B01** 确认四个界面的内容和完整用户流程。
- [x] **B02** 统一“已用/剩余”的数字、进度条和颜色含义。
- [x] **B03** 窗口时长与名称来自实际数据，不写死为“5 小时＋每周”。
- [x] **B04** 区分无数据、0%、100%、不支持和异常值。
- [x] **B05** 明确百分比精度、舍入规则、时间格式和时区规则。
- [x] **B06** 区分最后成功时间与最近尝试时间；失败不更新成功时间。
- [x] **B07** 定义重置时间已到但尚未获取新数据时的文案。
- [x] **B08** 覆盖未连接、加载、正常、旧缓存、离线、认证失效、服务异常状态。

## C. 账号与数据实现（M2）

账号与数据能力应覆盖首次连接、日常刷新、异常恢复和退出后的清理。

- [ ] **C01** 认证、额度请求、缓存和界面之间职责清楚，便于替换接入实现。
- [ ] **C02** 合并同账号并发请求，防止旧响应覆盖新结果。
- [ ] **C03** 账号退出或切换后，进行中的请求不能写回旧账号数据。
- [ ] **C04** 区分认证失败、无访问权限、限流、网络故障和服务异常。
- [ ] **C05** 未知附加字段可兼容；必要字段缺失时安全降级。
- [ ] **C06** 凭据加密保存，日志、诊断导出和备份中没有明文凭据。
- [ ] **C07** 退出后清除凭据和账号缓存，取消相关后台任务。
- [ ] **C08** 如支持远程撤销，区分本地退出成功与远程撤销成功。

## D. 小组件与生命周期（M3）

小组件单独验收，重点确认显示一致、交互明确、多实例共享数据，以及系统回收或重启后的恢复。

- [ ] **D01** 可通过系统组件选择器添加，并提供 App 内添加引导。
- [ ] **D02** 紧凑版和宽版在实际尺寸下都能读清主要数字与更新时间。
- [ ] **D03** 添加、取消配置、缩放、删除、重新添加均正常。
- [ ] **D04** 点击组件打开对应页面，刷新操作有反馈且不会重复触发请求。
- [ ] **D05** App 与所有组件展示同一份成功快照。
- [ ] **D06** 同时放置 3 个组件不会产生 3 份周期轮询。
- [ ] **D07** 退出后组件立即进入未连接状态，不残留账号数据。
- [ ] **D08** 进程回收、手机重启、应用升级后可恢复缓存和正常工作。
- [ ] **D09** 浅深色、大字体、窄尺寸和 TalkBack 可用，状态不只依赖颜色。

## E. 后台与真机稳定性（M3–M4）

在 M3 完成后台机制，M4 通过真机测试和连续自用检验延迟是否可解释、恢复是否可靠。设备覆盖优先包含实际自用手机。

- [ ] **E01** 周期任务唯一，重复进入 App 不会重复注册。
- [ ] **E02** 断网、恢复联网、超时、429、5xx 均按约定处理。
- [ ] **E03** Doze、系统省电和后台受限时没有崩溃或无限重试。
- [ ] **E04** 强制停止后重新打开 App，组件与同步能够恢复。
- [ ] **E05** 测试跨天、时区变化、夏令时和手动修改系统时间。
- [ ] **E06** 覆盖最低支持版本、Android 12、Android 15 及届时最新稳定版。
- [ ] **E07** 至少覆盖 Pixel/AOSP、Samsung、小米三类 Launcher；优先加入你的实际手机。
- [ ] **E08** 做 48 小时后台观察，记录请求数、实际刷新间隔、失败与耗电。
- [ ] **E09** 连续自用至少 7 天，记录登录稳定性、小组件显示和恢复问题。

强制停止场景以重新打开 App 后能够恢复为验收要求，不要求强停期间继续更新。相关平台约束与来源见开发计划。

## F. 公开发布准备（M5）

自用验证通过后，再确认发布渠道、签名升级、隐私说明与接口维护策略。

- [ ] **F01** 确认发布渠道：公开 APK 或 Google Play；核对对应发布要求。
- [ ] **F02** 固定包名、签名和版本管理方式，验证覆盖安装与数据迁移。
- [ ] **F03** 发布构建关闭调试信息，诊断内容完成脱敏。
- [ ] **F04** 隐私政策与实际数据流一致，说明数据获取方、保存位置和清除方式。
- [ ] **F05** 明确第三方产品身份，准备图标、截图、简介和帮助说明。
- [ ] **F06** 对外准确描述支持的账号、刷新限制和已知问题。
- [ ] **F07** 若后续收费，重新确认所采用接入方案的适用范围。
- [ ] **F08** 制定接口变化后的故障提示、修复发布和兼容策略。

## 最终验收目标

以下数字为建议目标，需在测试设备确定后冻结。此表描述后续版本应达到的状态，并非当前已通过的结果。

| 维度 | 验收目标 |
|---|---|
| 数据正确性 | 同一快照在 App 与组件中一致；缺失值不冒充零值。 |
| 新鲜度 | 所有额度展示都有最后成功时间；失败不伪装成更新成功。 |
| 性能 | 指定中档机缓存首屏 P95 ≤ 1 秒；正常环境下新快照落盘后组件更新 P95 ≤ 3 秒。 |
| 请求控制 | 1 个和 3 个组件的周期请求量基本一致，无请求风暴。 |
| 恢复能力 | 断网、凭据失效、进程回收、重启、升级均有通过记录。 |
| 凭据保护 | 日志、备份、导出和组件状态中没有明文凭据。 |
| 易用性 | 5 名目标用户中至少 4 名可独立完成连接、添加组件并读懂更新时间。 |
| 发布质量 | 连续自用 7 天，无未解决的崩溃、账号混用或额度误显示问题。 |
